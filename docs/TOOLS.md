# Tool reference

Every tool the server can register, generated from the live registry — do
not edit the catalog block by hand; run `scripts/gen_tool_docs.py` (see
[Regenerating](#regenerating)). Usage examples live in [USAGE.md](USAGE.md);
capability → token-scope mapping in [CAPABILITIES.md](CAPABILITIES.md).

## Conventions

| Convention | Behavior |
|---|---|
| Arguments | Flat JSON arguments on every tool, e.g. `{"issue_number": 1}`. A legacy `{"params": {...}}` wrapper is still accepted and unwrapped. Errors name the field and the expected shape. |
| Results | Success: `{"ok": true, "data": {...}}`. Failure: `{"ok": false, "error_type", "message", "suggestion", "request_id", "correlation_id"}` with `error_type` in `authentication`, `validation`, `not_found`, `rate_limit`, `internal`. |
| Access | `MCP_ACCESS_LEVEL=read\|write\|full` decides which tools are registered: `read` tools only, `write` (default) adds mutations, `full` adds the permanent deletes (each needs `confirm: true`). |
| Target | Tools act on `GH_PROJECT_ORG_NAME/GH_PROJECT_REPO_NAME` and project `GH_PROJECT_PROJECT_NUMBER`. With `GH_PROJECT_SCOPE_LOCK=true`, owner/repo/project overrides pointing elsewhere are refused. |
| Correlation | Every call gets a `correlation_id` that appears in the server log line and in the error envelope. |
| Language | The Markdown that the extended capability suite generates (comment templates, plans, roadmaps, reports) uses Spanish headings, e.g. `## Plan de implementación`, `## Registro de riesgos`. Tool names, descriptions and envelopes are English. |
| Heuristics | Suite tools named `suggest_*`, `detect_*`, `recommend_*`, `find_*` apply simple, documented keyword/field rules (see each summary below), not semantic analysis. |

## Regenerating

```bash
docker run --rm mcp-github-projects:latest python3 scripts/gen_tool_docs.py --check
```

`--check` exits 1 when this file is stale; `tests/test_tool_docs.py` runs the
same check in CI and also fails when any registered tool is missing here.
To rewrite the block, run the script without `--check` from a checkout and
commit the result (the image's `/app` is read-only, so mount or copy it back).
